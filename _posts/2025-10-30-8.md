## 1. 기본 개념

### 1) FPS (Frames Per Second)

**FPS란, 1초에 몇 장의 이미지를 보여줄 건가?** 를 결정하는 요소 입니다.

원본 영상이 30fps라고 해볼게요.
이 말은 1초에 30장의 이미지가 있다는 뜻이에요.

- `30 FPS` = 1초에 30장
- `10 FPS` = 1초에 10장

그런데, 원본 영상이 30fps니까, GIF도 30fps로 똑같이 뽑으면 어떨까요?
사실 조금 낭비일 수 있습니다.
사람 눈은 10~15fps 근처부터 '움직인다'고 느껴요. 그래서 그 아래로 내려도 괜찮습니다.
일부만 고르는 거예요.

```
FPS 높아질수록 → 움직임 부드러워짐 → 파일 크기 증가
```

### 2) 프레임 간격 (Frame Interval)

원본 영상이 30fps라고 해볼게요.
원본 영상이 30fps니까, GIF도 30fps로 똑같이 뽑으면 어떨까요?
사실 조금 낭비일 수 있습니다.
사람 눈은 10~15fps 근처부터 '움직인다'고 느껴요. 그래서 그 아래로 내려도 괜찮습니다.
일부만 고르는 거예요.

그래서 프레임 간격을 조정하는거죠.

- 간격 1 → 안 건너뜀 → 원본 프레임을 전부 사용
- 간격 2 → 1장 쓰고 1장 버리고 1장 쓰고 1장 버리고..
  원래 30장이면 → 실제로는 15장만 남음
- 간격 3 → 1장 쓰고 2장 버리고..
  30장 → 10장 남음
- 간격 5 → 1장 쓰고 4장 버리고..
  30장 → 6장 남음
  즉,
  프레임 간격이 클수록 → 더 많이 건너뛴다 → 실제 GIF에 들어가는 프레임 수가 줄어든다 → 움직임이 덜 부드럽다 → 대신 용량은 줄어든다

이렇게 됩니다.

이것을 10fps로 설정한다면?

### 3) 출력 가로 크기 (Width)

**GIF는 픽셀 수에 정말 민감합니다.**

- `1920px` → `960px`로만 줄여도 프레임 하나의 데이터량이 **대폭 줄어듭니다.**
- 가로만 줄여도 세로가 비례해서 줄어드니까 → 결국 **면적(픽셀 수)이 줄어듭니다.**

```
픽셀 수 높아질수록 → 파일 크기 감소 → 인코딩 시간 짧아짐
```

### 4) 품질 (Quality)

여기서 말하는 품질은:

- 팔레트 수 (몇 가지 색만 쓸지)
- 디더링(dithering) 세기
- 압축 레벨
- 색 양자화(quantization) 강도

```
품질 ↑ → 색을 더 유지 → GIF가 화려해짐 → 용량 ↑
품질 ↓ → 색을 덜 씀 → 밴딩/도트 느낌 생김 → 용량 ↓
```

## 2. 왜 이 4개가 서로 영향을 줄까?

GIF는 결국 **"프레임 수 × 프레임 하나의 무게"** 입니다.

```
GIF 전체 용량 ≈ (1초당 프레임 수) × (초 길이) × (프레임 1장의 픽셀 수) × (색정보 압축 정도)
                └──── FPS ────┘           └ width/height ┘   └ quality ┘
```

그러니까 4개를 이렇게 매핑할 수 있어요:

| 설정                  | 의미                                          |
| --------------------- | --------------------------------------------- |
| **FPS / 프레임 간격** | "프레임을 얼마나 자주 쓸 건데?"               |
| **출력 가로 크기**    | "프레임 한 장이 얼마나 무거울 건데?"          |
| **품질**              | "프레임 한 장을 얼마나 정교하게 저장할 건데?" |

**이 셋 중 두 개를 욕심내면 나머지 하나는 거의 무조건 포기해야 합니다.**

## 3. 조합별로 보면 더 쉽다

### (1) FPS 높음 + 큰 사이즈 + 높은 품질

**예**: 1080px, 30fps, 고품질

👉 **GIF 지옥 모드**입니다.

- 웹에서 거의 못 씁니다
- 5초만 돼도 몇십 MB
- **이 조합을 하고 싶으면 GIF 말고 MP4/WebM이 답**

### (2) FPS 낮음 + 큰 사이즈

**예**: 1080px, 8~12fps, 보통 품질

- 움직임이 살짝 끊기지만 **"영상 설명용 GIF"로는 괜찮음**
- 사이즈가 커서 **"디테일이 중요한 화면녹화"**에 많이 씁니다
- 여기서 프레임 간격을 키우는 것만으로도 용량이 확 줄어요

### (3) FPS 높음 + 작은 사이즈

**예**: 480px, 15~20fps

- 움짤 같고 부드러움도 어느 정도 있음
- **트위터/블로그/네이버 포스트**에서 많이 쓰는 패턴
- 가로 폭을 줄인 덕분에 FPS를 좀 살릴 수 있음

### (4) 작은 사이즈 + 낮은 FPS + 보통 품질 ⭐

👉 **가장 무난하고 웹 친화적인 GIF**

**예**: 480px, 10fps, 디더링 on

- 설명용, 미리보기용, 썸네일용으로 좋음
- **가장 추천하는 조합**

## 4. 하나씩 깊게 들어가보자

### 4-1. FPS ↔ 프레임 간격

원본 영상이 30fps인데 GIF를 30fps로 똑같이 뽑으면?

**→ 웹에서 보기엔 과합니다.**

사람 눈은 10~15fps 근처부터 "움직인다"고 느끼니까 그 아래로 내려도 종종 괜찮아요.

그래서 두 가지 방식이 나와요:

1. **직접 FPS를 낮춘다** (예: 30 → 12)
2. **프레임 간격으로 낮춘다** (예: 2프레임마다 1장만 저장)

#### 차이점은?

| 방식                | 특징                                       |
| ------------------- | ------------------------------------------ |
| **직접 FPS 낮추기** | 시간축이 다시 계산돼서 자연스러움 유지     |
| **프레임 건너뛰기** | 빠르게 움직이는 장면이 더 뚝뚝해질 수 있음 |

👉 **결론**:

- "움직임 자연스러움"을 중요시하면 → **FPS로 조절**
- "빠르게 대충 줄이기"면 → **프레임 간격으로 조절**

---

### 4-2. 출력 가로 크기 (Width)

**이게 진짜 효자입니다.**

`800px` → `400px`로만 줄여도 픽셀 수는 **1/4**이 됩니다.

```
(800×450) = 360,000px
(400×225) = 90,000px

👉 한 프레임 무게 자체가 4배 가벼워짐
```

그래서 **"GIF가 너무 커요" 문제는 대부분 FPS보다 먼저 사이즈를 줄이는 게 효과적**입니다.

특히 웹에서 WASM으로 인코딩하는 구조라면:

```
픽셀 수 ↑ → 브라우저 메모리 사용량 ↑
         → WASM 처리시간 ↑
         → 모바일에서 뻗음 💥
```

→ 그래서 **"먼저 리사이즈, 그다음 품질"** 순서가 좋아요.

---

### 4-3. 품질 (Quality)

GIF는 원래부터 **색을 256색까지만 쓸 수 있는 포맷**이라서
**색이 많은 영상(게임, 애니, 사진, 그라데이션)**일수록
품질을 높이면 용량이 미친 듯이 올라갑니다.

품질을 높인다는 건:

- 더 많은 색을 보존하고
- 디더링을 촘촘하게 넣고
- 프레임 간 차이를 더 정교하게 저장한다는 뜻

→ **프레임 1장당 데이터가 무거워짐**

그래서 **FPS를 높이면서 품질까지 높이는 건 거의 안 맞는 조합**이에요.

#### 👉 실전 팁:

1. 먼저 **가로 크기**를 정하고
2. 그다음 **FPS**를 대충 10~15로 맞추고
3. 마지막에 **품질**을 올려도 되는지 본다
   (= 여기서 터지면 품질을 내리는 게 맞음)

## 5. 실제 변환기에서의 우선순위

웹 GIF 변환기 구조를 생각하면, 보통 이렇게 가는 게 제일 안정적이에요:

### 1순위: 원본 리사이즈 먼저

브라우저/WASM이 견딜 수 있는 해상도로 ↓

```
예: 1920 → 720 또는 480
```

### 2순위: FPS 맞추기

```
30fps 영상 → 10~15fps 정도로
설명 GIF면 8~12fps도 충분
```

### 3순위: 그다음 품질

- gifski면 `--quality`, `--resize`, `--fps` 순서로
- ffmpeg면 `-vf fps=12,scale=480:-1:flags=lanczos` 이런 식으로 먼저 줄이기

**이 순서를 바꾸면** (예: 품질부터 올리고, FPS도 높이고, 마지막에 사이즈 줄이기)
→ 인코딩 시간이 괜히 길어지고, 메모리도 터지고, 모바일에서 뻗어요.

## 6. 흔한 질문에 미리 답하기

### Q1. "부드럽고, 크기도 작고, 화질도 좋은 GIF" 만들 수 없나요?

**A:** 솔직하게 말하면 **GIF 포맷 자체가 그걸 허용하지 않아요** 😂
그런 조합이 필요하면 **MP4/WebM, 아니면 APNG**로 가야 해요.

---

### Q2. "프레임 간격만 조절했는데 왜 화질이 떨어진 느낌이 나요?"

**A:** 프레임이 줄어들면서 **움직임이 끊겨 보여서** "화질"이 떨어진다고 느끼는 거예요.

실제 픽셀 화질이 아니라 **시간 해상도**가 떨어진 것입니다.

---

### Q3. "FPS를 낮췄는데 왜 여전히 커요?"

**A:** 아마:

- **가로 폭을 안 줄였거나**
- **배경이 전부 움직이는 화면**일 가능성이 높아요
  (= 프레임마다 차이가 커서 델타 압축이 잘 안 됨)
